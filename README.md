# 写作台

一个给中文长篇小说用的极简本地写作工具。外观模仿 VS Code（深色主题 + 假语法高亮），
但干的是写小说的活：自动分章、字数统计、Markdown 预览、内置 Git 提交。

零依赖：后端只用 Node 内置模块，前端是单页 HTML/CSS/JS，不需要 `npm install`，不需要构建。

![style](https://img.shields.io/badge/theme-VS%20Code%20Dark%2B-blue)

## 为什么

用 Word 或记事本写几十万字的连载，切换章节、看字数、提交 Git 都很别扭。
这个工具把「一章一个编辑区」当核心：编辑框里永远只有当前这一章（几千字），
所以再大的全书也不会卡，字数统计也只算当前章。

## 功能

- **自动分章**：识别 `第一章 xxx`、`第【3】段：第三章 xxx`、`第五回`、`序章 / 楔子 / 尾声 / 后记 / 番外`，中文章号（`十九`）与阿拉伯数字都支持。正文里偶然出现的「第三章 的伏笔」这类行会被过滤掉（章号必须单调递增）。
- **字数统计**：本章汉字 / 字符数、选中文字数、全书汉字合计，**章节标题不计入**。
- **Markdown 预览**：加粗、斜体、标题、表格、引用、代码块（把 `.md` 文件默认以预览打开）。
- **Git**：抓取 / 拉取 / 推送 / 提交全部改动，显示分支、领先落后提交数、改动文件、最近提交记录。
- **假语法高亮**：章节标题=函数黄、`"对话"`=字符串橙、`《书名》`=类型青、`（补充）`=注释绿、数字=数值绿、`忽然/但是/因为`=控制流紫。
- **自动保存**：停手 900ms、连续打字每 5 秒、切窗口、关窗口、切章节都会落盘；输入法组字期间暂停保存，不会打断候选。
- **懒加载**：超大文件（实测 2.9MB / 42 章）边扫描边出目录，字数后台慢慢填，解析结果显示进度；解析结果按文件缓存在内存，再次打开约 70ms。
- **写前备份**：每次写盘前把上一版备份到 `~/.config/novel-writer/backups/`（每个文件保留 20 份）。

## 运行

需要 Node.js 18+（开发环境是 Node 24）和任意 Chromium 系浏览器。

```bash
git clone https://github.com/zhangtao103239/novel-writer.git
cd novel-writer
node server.js          # 打开 http://127.0.0.1:7788
```

或者直接跑 `./run.sh`（会拉起服务并用 Chromium 以 app 模式开窗口）。

首次打开点右上角「…」选择你存放小说的 Git 仓库目录。仓库路径保存在
`~/.config/novel-writer/config.json`，也可以用环境变量覆盖：

| 变量 | 作用 |
| --- | --- |
| `NOVEL_PORT` | 服务端口，默认 7788 |
| `NOVEL_REPO` | 默认仓库路径 |
| `NOVEL_CONF_DIR` | 配置目录（多实例测试用） |

## 快捷键

| 键 | 作用 |
| --- | --- |
| `Ctrl+S` | 立即保存 |
| `Ctrl+Alt+←/→` | 上一章 / 下一章 |
| `Ctrl+P` | 编辑/预览切换（仅 Markdown） |

## 设计取舍

- **只监听 `127.0.0.1`**，没有登录鉴权，别暴露到公网。
- **编辑粒度是「章」**：切章 = 换文本，章节边界靠正则识别，不依赖额外索引文件。
- **不用框架**：没有 React/Vue/打包步骤，改一行刷新即可。代价是 DOM 操作是手写的。
- **大文件只读**：超过 40 万字符的文件不进入编辑态，避免 textarea 在大文本下掉帧
  （实测 10 万字单框每次按键 140ms，2000 字每章 0.12ms）。
- **输入法**：在 Wayland + fcitx4 的机器上建议用 `--ozone-platform=x11` 启动浏览器，
  让输入法走原生 X11，否则会经过一层兼容桥接。

